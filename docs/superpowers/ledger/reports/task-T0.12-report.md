# T0.12 report
Implemented in MapEditorPro.html (IO module + load handler) and tests/storage-errors.spec.ts (+10 tests). Full suite: 87 passed.
Deviations from the brief's literal code (all for the non-negotiables):
- _idb.set now also rejects on tx.onabort (quota failures on commit abort without onerror; old code would hang forever); open handles onblocked/onclose/versionchange.
- Write: legacy LS key removed only after IDB tx complete; on IDB failure/hang (8 s timeout) falls back to StorageGuard.setItem (warns if that fails) and keeps the legacy key.
- Each saved JSON gets `_autosavedAt` (monotonic ms); restore parses both copies, validates shape, newest wins, tie -> IDB; corrupt/non-string/wrong-shape copies skipped; if nothing loads and a copy was unreadable, a sticky toast warns.
- Restore: IDB read has 8 s timeout (falls to LS); if mapData was replaced while the read was pending the restore is dropped. Startup awaits restore before Canvas/UI init and sync, so UI cannot race it.
- Flush handlers (beforeunload/pagehide/visibilitychange hidden, and the 30 s interval) go through a try/catch wrapper; snapshot built synchronously; IDB orders overlapping writes so the last wins.
- _autoSave catches _buildJson errors (StorageGuard._warn) and returns a promise that never rejects.
- Updated existing test 'map autosave failure is surfaced' to also fail IDB.
Tests added: IDB home+reload, legacy restore then retire (legacy kept until write), quota put fallback + double failure warning, aborted tx, IDB unavailable, hanging read, both present newest wins (both directions), corrupt records, restore-vs-opened-map race, flush handlers/last write wins.
Concerns: a pagehide IDB write is best effort (browser may kill it; previous copy then remains, as no sync localStorage write is done to avoid the quota); a stale LS copy left after a late fallback is harmless (older ts) but keeps using quota until the next successful IDB write. RED run was not captured separately (old code obviously lacks IDB/ts).

## Round 4 (new implementer; design ruling: side copies are never deleted automatically, never stale)
Changes (MapEditorPro.html, commit ad58049):
- Rotation/staleness scheme removed entirely (`_rotateSide`, `_removeSide`, `_SIDE_KEYS`, `_sideLocked`, `_pendingOffer`, `_restoredInfo`, `offerPendingRestore`, the `pc.ts < cands[0].ts` deletion, and the side-copy removal after a main-slot commit). `_lastStamp` is still seeded from every side copy.
- Protected-mode saves go to this page load's own snapshot key `map_side_<firstStamp>_<rand4>` in IndexedDB `kv` (overwritten only by the same page load's later flushes). If the IndexedDB write fails/times out, the same key is written to localStorage via StorageGuard (warns on failure); a localStorage key that exists and is not ours is never written.
- A protected map that is unchanged since it was read (restored main record, or a restored side copy) writes no side copy (`_sideBaseline`), so reloads with a broken IndexedDB do not pile up copies.
- Cap 10: when a new session key would be the 11th copy, nothing is written and a sticky toast says "Too many unrecovered autosave copies — open File > Recover autosave copies… to restore or discard them" (shown once; removed when copies drop below the cap).
- Every startup (`_readAutosave` → `_refreshSides`) lists IndexedDB `map_side_*` + localStorage `map_side_*` + legacy `map_autosave_pending` / `_prev` (each its own row). If any exist, one dialog lists rows (local time, KB via Math.max(1,…), "(unreadable)" rows get Discard only) with per-row Restore / "Discard (cannot be undone)"; dialog-level "Decide later" / Escape / superseding dialog leave everything. The dialog re-renders until all rows are handled. All autosave writes are suppressed while it is open (`_recoveryOpen`); Restore writes the main slot directly and deletes only that copy after a verified commit (in protected mode there is no main commit, so the copy is kept and the toast says so). The new-map prompt follows the dialog when no map is on screen (`IO.hasUserMap()`).
- Menu choice: added "File > Recover autosave copies…" (`IO.openRecoveryDialog(true)`: flushes the current map first, re-lists, opens the same dialog). Also added `UI.closeDialog(result)` (used to close the dialog when all rows are handled) and `_idb.entries(prefix)` / `_idb.del(key)`.
- N-C: `tryRestoreAutosave(override)` snapshots MAP_WIDTH/HEIGHT, mapData, bridgesData, objectsData, tileExtras, roadsData, settlements, settlementSlots, priorities, file name and ZonePainter state; on a throw it puts all of it back; `_protected`/`_userMap` are not touched; toast "Could not restore this autosave copy — Nothing was changed … the copy was left intact … Autosave works as before".
- Kept: protected mode triggers, startup-modal Create keeps protection, `_userMap` gate (set by successful restore, applyNewMap, _loadFromJSON), `_endProtection` placement, strict durability, StorageGuard.ok, late-commit cleanup, `window.__autosaveIdbTimeoutMs`. Protected toast text now also mentions the recovery copies.
