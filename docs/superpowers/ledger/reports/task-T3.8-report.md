# T3.8 report: placement helper (bunkers, mega cities, artifacts, ore clusters)
## What / where (MapEditorPro.html)
- `Placement` module before `autoPlaceSettlements()`. ALL assumptions (ids, kinds, counts, min distances, ore list, ore spacing) live in ONE `CONFIG` object (`Placement.defaults()` returns a copy). `plan(cfg, seed)` only reads the map (seeded `HexUtils.makeRng`, T3.7 `GenUtils` primitives); `place(cfg, seed)` is the bulk writer; `apply()` reads/validates the palette; `buildUI()` builds the controls with DOM APIs.
- UI: LEFT palette, inside the closed-by-default `#map-design` section (seed, bunkers, mega cities, artifacts, 4 ore cluster counts, Place button). Nothing in the toolbar or right panel; canvas 1491x808 at 1400x900 (tested). Inputs are strict (whole numbers; bunkers 0..5000, mega 0..100, artifacts 0..200, ore clusters 0..100, seed 0..4294967295 or empty = random, shown in the seed placeholder and the toast); bad value: one toast naming the field, no step, no write; no alert().
- Writer contract: `Tools.guardBulkWrite(layers)` with only the layers the run really writes (settlements for bunkers/mega, objects for artifacts, terrain for ore clusters; a zero count does not need its layer), so busy fill, active stroke or lifted move, and locks refuse with a toast before any step. Plan first, then ONE `History.push()` token before the first write; nothing placeable -> no step and a toast; an exception -> `History.rollback(token)`, map restored, toast. `bumpMapWrite()` after the write; autosave, render, minimap; hidden settlements/objects layers are shown (like Auto-place). No awaits, so no map-identity race.
- Eligible cells: land only (Water, Rivers, Hills/Mountains, Volcanic/Rift and unknown tiles excluded), inside the map, not the city cell, no settlement/building/road/bridge, never a multi-tile terrain anchor or footprint cell. Ore tiles are written only onto such free cells; multi-tile ore tiles and artifact buildings that spawn satellites are skipped with a reason. Settlements `{col,row,type}`, objects `objectsData[key]=id`, ore as terrain: all erasable/paintable by the normal tools (tested with real clicks).
- No new tool, so nothing to add to `TOOL_LAYER` and the tool-based lock matrix in layers.spec.ts (its inventory test still passes); the lock matrix for this command is in placement.spec.ts.
## Decisions / deviations from the brief
- Controls in the palette, not the Generate menu/modal (ruling). `plan`/`place` split instead of `run` (no empty History step).
- A lifted MOVE is refused by the shared guard (it counts as an active gesture), so it is not cancelled; a paste preview is not blocked. Tested as such.
- Ore writes do not call `autoResolveEdgesAround`: ore tiles are not edge-family and water cells are never overwritten, so no edge changes (it would also use Math.random).
- Ore tiles skip cells already used by earlier picks; Poisson spacing is shared across mega cities, artifacts and ores.
