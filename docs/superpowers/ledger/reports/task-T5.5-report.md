# T5.5 report: searchable reskin picker with sprite previews
Changed: MapEditorPro.html (Packages.openReskinPicker, HexDB/BldDB.promptReskin, CSS), new tests/packages-reskin.spec.ts (9 tests), tests/no-native-dialogs.spec.ts (3 reskin tests moved from the old select dialog to the picker).
- `Packages.openReskinPicker({kind, entries, onPick})` on `UI.showModal` (id `reskin-picker-modal`, DOM nodes only): search input `#reskin-search` (autofocus, role searchbox), `#reskin-count`, listbox `#reskin-list` of `button.reskin-item[data-id]` (role option, `aria-selected` on the active one, `aria-activedescendant` on the input), `#reskin-empty` for no results. Ids/names via textContent/dataset only (hostile id test: no injected element, no script, picked verbatim).
- Previews: `Packages.spriteSrc` (package-aware), `<img loading=lazy>` created only for rendered entries, render cap 60 with "Showing first 60 of N" text; missing sprite gets class `no-sprite` (dimmed). Entries already reskinned by the active package are disabled (click, arrows and Enter skip them).
- Keyboard: ArrowDown/ArrowUp move through enabled entries, Enter picks the active one (first enabled after every filter), Escape (modal) closes with no change and returns focus to the button; Cancel button likewise. IME composition ignored.
- Semantics unchanged: picker returns the id to `addReskin` (copy of the base entry, same id, active package, base untouched); both `promptReskin` keep the non-default-package guard and the "nothing to reskin" toast. `window.prompt`/`UI.prompt` no longer used for reskin.
- Debounce: filtering is synchronous (hundreds of string matches, rendering capped), so there is no timer to wait for in tests.
RED: 8/9 failed (the default-package toast test already held). GREEN: 9/9. Mutation: arrow navigation without the disabled filter fails the keyboard test; restored with cmp.
Pixel check: a registered red 8x8 sprite is drawn from the preview <img> into a canvas and the centre pixel is read (r>200, g,b<40); negative control: the missing sprite item has `no-sprite`, the red one does not.
Focused run: new spec + package-*, packages-*, registry-fresh-read, startup-sync, validator-core/ui, modal, dialogs, no-native-dialogs, layout-narrow, layers, phase5-helpers, perf-terrain-memo = 360 passed.
Not done: picker shows only base (postapoc) entries as before (reskinning another package's entry is not offered); no thumbnail preloading beyond the browser's lazy loading.
