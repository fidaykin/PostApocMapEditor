Data Sync Guide

Map Editor ↔ Google Drive ↔ Unity App — runtime hex database and sprite sync.

This guide explains how terrain hex definitions (types, properties, sprites) you create in MapEditorPro reach a live Unity build on device — without recompiling or rebuilding the app. The same Google Drive folder already used for map JSON files also holds the hex database and sprite PNGs.

🗺️
Map Editor (browser)
Edit hex types · assign sprites · export hex_database.json + PNGs
↓ upload to Google Drive
☁️
Google Drive Folder
hex_database.json + hex_*.png + map JSON files — all in one folder
↓ tap "Sync Database" in-app
📱
Unity App (device)
Downloads DB + sprites · patches TileRenderer live · redraws map
No rebuild needed. Sprite and property changes for existing terrain types apply instantly on the running app. You only need a code rebuild when adding a brand-new TerrainType enum value — see Limitations.

Unity Setup (one-time)

Do this once after pulling the latest code. You will not need to repeat it.

Step 1 — Add RuntimeDatabaseSync to the scene

  1. Open Assets/_Project/Scenes/Game.unity.

  2. Find the GameObject that already holds GoogleDriveMapLoader (usually a manager GO called Managers or MapLoader).

  3. In the Inspector click Add Component → PostApoc.Map → RuntimeDatabaseSync.

    Inspector — RuntimeDatabaseSync component

    The Folder ID and API Key default to the same values already used by GoogleDriveMapLoader — no configuration needed unless you use a different folder.

Step 2 — Add a "Sync Database" button to the Map panel

  1. In the scene hierarchy, navigate to the MapListPanel GameObject (the panel that lists downloadable maps).

  2. Add a new Button inside the panel. Name it SyncDb_Button. Set its label text to Sync Database.

  3. Select the MapListPanel component. Drag SyncDb_Button into the Sync Db Button slot.

Map Editor Export

After editing hex types in MapEditorPro (HexDB tab), export the data so it can be uploaded to Google Drive.

  1. Open MapEditorPro in your browser.

  2. Go to the HexDB tab. Add or edit terrain hex entries — set the Id, Type, and Sprite Name for each terrain type.

    Sprite Name must match the PNG filename you will upload (without the .png extension). For example: sprite name hex_rubble_2 → upload file hex_rubble_2.png.

  3. Click File → Export All (or use the export shortcut). Save hex_database.json to a local folder.

  4. Copy any new or updated terrain sprite PNGs into the same local folder. Name them to match the Sprite Name fields:

Google Drive Upload

Upload the exported files to the shared Drive folder (folder ID 1740gOYYEbZeTMEm5BQgga4JguOC7Di1Q — same folder used for map JSONs).

  1. Open the shared Google Drive folder in your browser.

  2. Upload hex_database.json. If a file with that name already exists, choose Replace existing file — Google Drive will update it in-place and preserve the same file ID, so no config change is needed in Unity.

  3. Upload any new or changed PNG files. Existing PNGs can be replaced the same way.

    Unchanged PNGs do not need to be re-uploaded. The app downloads each sprite listed in hex_database.json that has a matching file in the folder — so only new or changed ones need to be there.

  4. Make sure all uploaded files are publicly accessible (or accessible with the API key). The folder's share settings propagate to files uploaded into it, so this usually requires no extra action if the folder is already set to Anyone with the link → Viewer.

Replace, don't delete. If you delete a file and re-upload it, Google Drive assigns a new file ID. The app looks files up by name, not ID, so a re-upload is safe — but deletion will briefly make the file invisible until the new upload completes.

Runtime Sync (In-App)

Trigger a sync at any time from within the running game.

  1. Open the Map panel (tap the Maps tab in the bottom HUD).

  2. Tap Sync Database. The status line shows progress for each file downloaded:

    Map panel — status text during sync
    Connecting to Google Drive…
    Downloading hex_database.json…
    Downloading hex_rubble_2.png…
    Rebuilding map visuals…
    ✓ Sync complete: 12 tiles updated, 0 skipped

  3. The map redraws immediately with the new sprites. No scene reload or app restart needed.

Sync requires an active internet connection. If the Drive folder is unreachable the status line shows an error message — the existing tiles remain unchanged.

What Gets Synced

Data Synced at runtime Notes
Terrain tile sprite Yes PNG downloaded → Texture2D → Sprite → Tile → VisualTile override
Terrain type (Type field) No Enum value — set at import time via DatabaseImporterWindow in the Editor
IsBuildable, ExplorationCost No ScriptableObject fields — use DatabaseImporterWindow for those
Map terrain grid Separate Handled by GoogleDriveMapLoader + RuntimeMapApplier (map JSON download flow)
Two sync flows, one folder. The DB sync (this guide) updates which sprite each terrain type looks like. The Map sync (existing maps panel) updates which terrain type each hex cell is. Both flows read from the same Drive folder independently.

Limitations

New terrain types require a code rebuild

The TerrainType enum is compiled C# code. Adding an entirely new terrain type (e.g. Volcano_2) requires:

  1. Adding the value to TerrainTypeDefinition.cs
  2. Running PostApoc → Import Hex Database in the Unity Editor
  3. Building and deploying a new APK

However — updating the sprite of any existing terrain type (all 29 types in the current enum) works fully at runtime via DB sync. This covers the most common workflow: designing and iterating on terrain visuals.

Synced tiles are in-memory only

Tiles created at runtime by RuntimeDatabaseSync are not saved as Unity assets. They exist only while the app is running. Each app session starts from the base compiled ScriptableObjects; a sync re-applies the Drive versions. This is intentional — the base assets are the fallback if Drive is unreachable.

Sprite pixel-per-unit must match at the source

Sprites are loaded at 100 pixels-per-unit (the Unity tilemap standard). If your PNGs are designed at a different resolution, the tiles may appear larger or smaller than the hex grid. Design sprites at the same pixel dimensions as the existing terrain tiles.

To check existing tile sizes: inspect any TerrainTypeDefinition asset in Assets/_Project/Data/Terrain/ — the linked Tile references a sprite whose texture width × height tells you the target resolution.
